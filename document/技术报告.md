## 摘要

本文介绍了一款面向 2026 年全国大学生电子设计竞赛的智能循迹小车系统。该系统以 STM32F407VET6 微控制器为核心，集成 K230 视觉模块、JY901S 惯性测量单元（IMU）、TB6612 双路电机驱动及增量式编码器，构建了"感知—决策—执行"三层闭环控制架构。系统创新性地提出**双模切换策略**——在视觉循迹模式与陀螺仪盲开模式间自动切换，解决了弯道丢线、原地转向等场景下的连续控制难题。经实测，小车能够在 220cm × 120cm 的椭圆形场地上完成指定路线的自动行驶任务。

**关键词**: 智能小车；PID 控制；双模切换；视觉循迹；IMU 惯性导航；STM32

## 一、系统方案

### 1.1 赛题分析

赛题要求设计一辆智能小车，在给定的"体育场跑道"形场地上（如图 1-1 所示），从起点 A 出发完成以下任务：

| 任务 | 路线 | 约束条件 | 分值 | 时间限制 |
|:----:|------|----------|:----:|:--------:|
| 任务(1) | A → B（直线） | 到达 B 点停车并发出声音提示 | 20 | ≤ 15 s |
| 任务(2) | A → B → C → D → A（外圈） | 每节点有声音提示 | 20 | ≤ 30 s |
| 任务(3) | A → C → B → D → A（内切） | 声音提示；尽量少停车 | 30 | ≤ 40 s |
| 任务(4) | 行驶中恰好停车 4 次 | 对前述任务的附加约束 | 30 | — |

场地参数如下：

- **外框总尺寸**: 220 cm × 120 cm
- **圆弧段**: 左右对称半圆弧，半径 R = 40 cm
- **顶部直线段 AB**: 100 cm
- **右侧圆弧圆心**: 距场地右边界 60 cm，距下边界 60 cm（处于中轴线上）
- **左侧圆弧圆心**: 与右侧对称分布

### 1.2 总体方案论证

#### 方案一：纯视觉循迹

仅依赖摄像头进行黑线检测与跟踪。**优点**：结构简单，直线段循迹精度高。**缺点**：在圆弧段由于摄像头视场角的限制可能出现丢线；当黑线完全脱离摄像头视野时，小车将完全失控。

#### 方案二：纯 IMU 惯性导航

仅依赖陀螺仪/加速度计进行航位推算。**优点**：不受光照和场地条件影响，可靠性高。**缺点**：陀螺仪存在积分漂移，长时间运行累积误差不可忽略；无法感知实际黑线位置。

#### 方案三（本系统采用）：视觉 + IMU 双模融合

结合 K230 视觉模块的 6 路灰度循迹与 JY901S 陀螺仪的角度姿态数据，设计**双模自动切换策略**：

- **模式 A — 盲开模式**：当 `line_sensor_data == 0x00`（所有灰度传感器均未检测到黑线）或 `base_speed == 0`（原地转向）时，完全依赖陀螺仪 Yaw 角进行角度环 PID 保持。
- **模式 B — 循迹模式**：当至少一路灰度传感器检测到黑线时，使用 K230 实时计算的转弯偏差量修正航向。

该策略在直线段充分利用视觉的高精度循迹优势，在圆弧段/丢线瞬间依靠陀螺仪惯性导航平滑过渡，两者互补，保证行驶的连续性和稳定性。

## 二、理论分析与算法设计

### 2.1 增量式 PID 控制器

系统采用**增量式 PID** 算法，其数学表达如下：

$$
\Delta u(k) = K_p [e(k) - e(k-1)] + K_i \cdot e(k) + K_d [e(k) - 2e(k-1) + e(k-2)]
$$

$$
u(k) = u(k-1) + \Delta u(k)
$$

其中 $e(k)$ 为第 $k$ 个采样周期的偏差，$K_p$、$K_i$、$K_d$ 分别为比例、积分、微分系数。

**增量式 PID 的优势**：
- 输出为增量，误动作影响小，切换冲击小
- 无需累加全部历史误差，不会因积分饱和导致失控
- 便于实现无扰切换

### 2.2 PID 参数整定

系统共配置三组 PID 控制器，参数如下：

| PID 环路 | Kp | Ki | Kd | 输出限幅 | 控制目标 |
|----------|:--:|:--:|:--:|:--------:|----------|
| 左轮速度环 | 0.9 | 0.12 | 0.0 | ±500 | 跟踪左轮目标转速 |
| 右轮速度环 | 0.8 | 0.12 | 0.0 | ±500 | 跟踪右轮目标转速 |
| 角度环 | 0.8 | 0.0 | 0.9 | ±40 | 保持/修正目标偏航角 |

**设计要点**：
- **速度环采用 PI 控制**（$K_d = 0$）：编码器采样存在随机噪声，微分项会放大噪声引入不稳定因素
- **角度环采用 PD 控制**（$K_i = 0$）：比例项快速纠偏，微分项抑制超调振荡；不使用积分项避免积分饱和导致原地打转
- **左右轮速度环 Kp 略有差异**（0.9 vs 0.8）：补偿两个电机的机械特性不一致
- **输出限幅**：速度环限幅 ±500 防止 PWM 饱和，角度环限幅 ±40 防止过激转向

### 2.3 双模切换算法

双模切换是本系统循迹策略的核心创新，其决策逻辑如下：

```
若 line_sensor_data == 0x00 或 base_speed == 0:
    → 模式 A（盲开模式）
      角度误差 = target_angle - current_angle
      turn_out = PID_Compute(&pid_angle, angle_error, 0)
否则:
    → 模式 B（循迹模式）
      turn_out = K230_Get_Turn_Speed(line_sensor_data)
      target_angle = current_angle  // 同步角度，防止切回时抖动
```

**模式切换边界条件**：
- `line_sensor_data == 0x00`：6 路灰度传感器全白，说明黑线已脱离视场
- `base_speed == 0`：原地转向阶段，强制屏蔽摄像头数据，仅依赖陀螺仪角度环精确控制转向角度
- 切回循迹模式时同步 `target_angle = current_angle`，避免因角度目标跳变导致车体剧烈抽搐

### 2.4 转弯偏差映射

K230 视觉模块将 6 路灰度数据编码为 6 位二进制值（bit5 ~ bit0），STM32 端通过查表法将传感器状态映射为转弯速度修正量：

| 传感器值 | 二进制 | 含义 | 转弯量 |
|:--------:|:------:|------|:------:|
| 0x0C | 001100 | 正中压线 | 0 |
| 0x08 | 001000 | 略偏右 | +2 |
| 0x04 | 000100 | 略偏左 | -2 |
| 0x18 | 011000 | 微偏右 | +3 |
| 0x06 | 000110 | 微偏左 | -3 |
| 0x1C | 011100 | 中度偏右 | +5 |
| 0x0E | 001110 | 中度偏左 | -5 |
| 0x10 | 010000 | 单路偏右 | +8 |
| 0x02 | 000010 | 单路偏左 | -8 |
| 0x20 | 100000 | 极度偏右 | +12 |
| 0x01 | 000001 | 极度偏左 | -12 |

对于未在表中匹配的异常值（如读到的线过宽或噪声），保持上一周期的转弯量，避免突然回正造成失控。

### 2.5 节点计数与去抖

节点计数用于判断小车行驶到的位置，驱动任务状态机阶段切换。算法基于黑线状态的**边沿检测**：

- 每 20 ms 检测一次 `line_sensor_data`
- 将其二值化为 `current_line = (line_sensor_data != 0x00)`
- 若 `last_line_status ≠ current_line`，说明发生了黑白翻转，触发 `count++`
- 触发后进入 300 ms 冷却窗口（15 个中断周期），防止因传感器在边界附近抖动导致重复计数

### 2.6 角度突变过滤

JY901S 陀螺仪在部分场景下可能输出异常 Yaw 值（如外部磁场干扰），系统设立了角度突变过滤器：

- 计算 20 ms 内 Yaw 角变化量 `diff = raw_yaw - last_valid_angle`
- 进行 ±180° 角度规范化处理
- 若 `|diff| > 30°` 且上次有效角度非零，丢弃当前读数，沿用 `last_valid_angle`
- 否则更新 `last_valid_angle`

该过滤器有效抑制了陀螺仪的偶然异常跳变，避免了因瞬时 Yaw 错误值导致的角度环 PID 过冲。

### 2.7 转弯输出平滑滤波

在循迹模式下，K230 的转弯偏差输出可能因传感器离散采样而存在抖动。系统引入一阶低通滤波器进行平滑处理：

$$
turn_{smooth}(k) = 0.7 \times turn_{smooth}(k-1) + 0.3 \times turn_{raw}(k)
$$

较大的历史权重（0.7）使转弯输出变化更加平缓，有效抑制了传感器数据突变引发的车体摆动。

### 2.8 速度合成公式

最终的左右轮目标速度由基础速度和转弯修正两部分合成：

$$
v_{left} = base\_speed - turn\_smooth
$$

$$
v_{right} = base\_speed + turn\_smooth
$$

**速度分配策略**：
- 直线段：`base_speed = 60`，高速巡航
- 圆弧段：`base_speed = 30`，降速保证弯道循迹稳定性
- 原地转向：`base_speed = 0`，仅依赖角度环 PID 扭正车头

### 2.9 任务状态机设计

#### 任务(1) — count 驱动

最简单的直线任务，`count == 0` 时直行 60 速，`count >= 1` 时停车。

#### 任务(2) — count 驱动 + C 点精密对准

采用 5 段 count 驱动策略：

| count | 路段 | 目标角度 | 基础速度 | 特殊处理 |
|:-----:|------|:--------:|:--------:|----------|
| 0 | A → B | 0° | 60 | 直线高速 |
| 1 | B → C | -90° | 30 | 弯道减速 |
| 2 | C 点 | -180° | 0→60 | **精密对准**：停车，角度误差 < 1° 后发车 |
| 3 | D → A | -270° | 30 | 弯道减速 |
| ≥4 | 终点 | — | 0 | 停车 |

C 点精密对准是 Task 2 的关键设计：在 C 点完全停车，依靠角度环 PID 将车头精确扭转到 -180° 方向，待误差小于 1° 后方可发车冲刺 C→D 直线段。该策略有效避免了盲开直线时的角度累积误差。

#### 任务(3) — 9 状态航点状态机

采用 `task3_state` 驱动 9 个状态的流转，每个弯道节点执行"停车-旋转-发车"三阶段流程：

| 状态 | 动作 | 目标角度 | 基础速度 | 触发条件 |
|:----:|------|:--------:|:--------:|----------|
| 0 | A 点旋转 | -39° | 0 | 误差 < 2° / 超时 |
| 1 | A→C 盲开 | -39° | 60 | count ≥ 1 |
| 2 | C 点旋转 | 0° | 0 | 误差 < 5° |
| 3 | C→B 循迹 | 动态 | 30 | count ≥ 2 |
| 4 | B 点旋转 | -144° | 0 | 误差 < 2° |
| 5 | B→D 盲开 | -144° | 60 | count ≥ 3 |
| 6 | D 点旋转 | 180° | 0 | 误差 < 5° |
| 7 | D→A 循迹 | 动态 | 30 | count ≥ 4 |
| 8 | 终点停车 | — | 0 | — |

**设计亮点**：
- A 点和 B 点偏转角 -39° 和 -144° 对应场地对角线方向
- 循迹前转向精度放宽至 5°（K230 将在后续循迹阶段在线修正）
- 盲开前转向精度收紧至 2°（无视觉辅助，全依赖陀螺仪）
- 弯道循迹中动态更新 `target_angle = current_angle - 15°`，赋予车头持续右弯的引导趋势，防止卡顿

#### 任务(4) — 33 状态展开多圈状态机

将 4 圈 × 每圈 8 段 = 32 个推进状态完全展开为独立的 case，每圈可独立微调目标角度：

- **第一圈**（状态 0~7）：A 偏转 -39° → A→C 盲开 → C 偏转 0° → C→B 循迹 → B 偏转 -144° → B→D 盲开 → D 偏转 180° → D→A 循迹
- **第二圈**（状态 8~15）：A 偏转微调为 -36°、C 偏转微调为 -145°
- **第三圈**（状态 16~23）：A 偏转微调为 -38°、C 偏转微调为 -146°
- **第四圈**（状态 24~31）：A 偏转复位 -39°、C 偏转保持 -146°
- **状态 32**：终点停车

展开状态机的优势：每圈独立参数空间，便于根据实跑情况逐圈微调，无需受循环变量约束。

### 3.2 电机驱动电路

TB6612FNG 双 H 桥驱动芯片，支持双路直流电机独立正反转与 PWM 调速：

| 信号 | STM32 引脚 | 说明 |
|------|-----------|------|
| AIN1 (左轮正向) | PE2 | 高电平 = 正向 |
| AIN2 (左轮反向) | PE3 | 高电平 = 反向 |
| PWMA (左轮调速) | PA6 (TIM3_CH1) | PWM 占空比 0~999 |
| BIN1 (右轮正向) | PE4 | 高电平 = 正向 |
| BIN2 (右轮反向) | PE5 | 高电平 = 反向 |
| PWMB (右轮调速) | PA7 (TIM3_CH2) | PWM 占空比 0~999 |
| STBY (待机) | PE6 | 高电平 = 使能 |

PWM 频率：TIM3 预分频 84-1，周期 100-1，定时器时钟 84 MHz → 10 kHz。

### 3.3 编码器接口

| 编码器 | TIM 通道 | 引脚 | 模式 |
|--------|----------|------|------|
| 左轮 | TIM2 CH1/CH2 | PA0/PA1 | 编码器模式 ×4 |
| 右轮 | TIM4 CH1/CH2 | PD12/PD13 | 编码器模式 ×4 |

定时器以编码器模式运行，自动对正交编码脉冲进行增减计数，每 20 ms 读取一次计数值作为轮速反馈。

### 3.4 传感器通信接口

| 传感器 | 接口 | 波特率 | STM32 引脚 | 协议 |
|--------|------|:------:|-----------|------|
| K230 摄像头 | USART3 | 115200 bps | PB11(RX) | 3 字节帧：0xAA + 0x55 + data |
| JY901S IMU | USART2 | 9600 bps | PA3(RX) | 11 字节帧：0x55 + ... + 校验和 |

### 3.5 人机交互与指示

| 功能 | 引脚 | 说明 |
|------|------|------|
| OLED 显示 | PB6(SCL), PB7(SDA) | 软件模拟 I2C（开漏输出），显示任务/状态/角度 |

## 四、软件设计

### 4.1 软件架构总览

系统采用**分层模块化**设计，目录结构如下：

```
H0/
├── Core/Src/main.c          主程序（初始化 + 主循环 + TIM6 中断）
├── Drive/                   用户自定义驱动层
│   ├── Motor.c/h            TB6612 电机驱动
│   ├── encoder.c/h          编码器读取
│   ├── pid.c/h              通用增量式 PID
│   ├── wit_imu.c/h          JY901S 数据解析
│   ├── k230_track.c/h       K230 视觉解析 + 转弯量计算
│   ├── task.c/h             任务管理（按键 + 状态机）
│   ├── oled.c/h             OLED 显示
│   └── led_beep.c/h         LED + 蜂鸣器
├── Drivers/                 ST HAL 库
└── untitled_1.py            K230 端 Python 程序
```

### 4.2 主程序流程

```
系统上电
   │
   ▼
HAL 初始化 + 系统时钟配置 (168MHz)
   │
   ▼
外设初始化: GPIO → TIM2/3/4/6 → USART1/2/3
   │
   ▼
驱动初始化: Encoder → Motor → OLED → PID ×3 → 按键
   │
   ▼
开启 UART2/UART3 接收中断 + TIM6 周期中断
   │
   ▼
   ┌─────────────────────────┐
   │    while(1) 主循环       │
   │                         │
   │  Task_Dispatcher()      │  ← 运行当前选中任务的状态机
   │  OLED 数据刷新          │
   │  HAL_Delay(10)          │
   └─────────────────────────┘
```

### 4.3 TIM6 中断服务流程（20 ms 核心节拍）

```
TIM6 中断触发 (每 20ms)
   │
   ▼
1. 按键扫描 (Task_Key_Scan)
   │
   ▼
2. 节点计数去抖
   ├── 读取 current_line = (line_sensor_data != 0x00)
   ├── 双边沿检测: last_line_status ≠ current_line → count++
   └── 冷却窗口: 15 周期 (300ms)
   │
   ▼
3. 角度突变过滤
   ├── raw_yaw = IMU_Data.Yaw - Yaw_Offset
   ├── diff = raw_yaw - last_valid_angle
   ├── |diff| > 30° → 丢弃，沿用上次值
   └── |diff| ≤ 30° → 更新
   │
   ▼
4. 双模切换决策
   ├── line_sensor_data == 0x00 或 base_speed == 0
   │   → 模式A: 角度环 PID(turn_out = PID(angle_error))
   └── 否则
       → 模式B: K230_Get_Turn_Speed() 查表
       → 同步 target_angle = current_angle
   │
   ▼
5. 转弯输出平滑
   turn_smooth = 0.7 × old + 0.3 × new
   │
   ▼
6. 差速合成
   v_left  = base_speed - turn_smooth
   v_right = base_speed + turn_smooth
   │
   ▼
7. 双轮速度环 PID
   ├── 左轮: 编码器低通(0.7*old+0.3*raw) → PID → PWM
   └── 右轮: 编码器低通(0.7*old+0.3*raw) → PID → PWM
   │
   ▼
中断返回
```

### 4.4 K230 端视觉处理

K230 开发板运行 MicroPython 程序，流程如下：

```
初始化: 摄像头(640×480) + 显示屏 + UART2(115200bps)
   │

```

**ROI 区域划分**：6 个区域水平排列在图像底部（y = 360），每区宽 106 px、高 60 px，覆盖 640 px 宽度。

### 4.5 JY901S IMU 数据解析

JY901S 通过 UART2 以 9600 bps 速率持续发送 11 字节数据帧，STM32 端采用**字节状态机**进行解析：

```
状态0: 等待 0x55 (帧头) → 状态1
状态1: 累计接收至 11 字节 → 校验和验证 → 根据 frame[1] 解析:
  ├── 0x51 → 加速度数据 (AccX, AccY, AccZ)
  ├── 0x52 → 角速度数据 (GyroX, GyroY, GyroZ)
  └── 0x53 → 角度数据 (Roll, Pitch, Yaw)
```

每次 UART 接收中断只接收 1 个字节，接收完毕后立即重新使能中断，保证数据流的连续性。

### 4.6 PID 控制器实现

```c
// PID 结构体
typedef struct {
    float target;      // 目标值
    float Kp, Ki, Kd;  // PID 系数
    float error;       // 当前误差
    float last_error;  // 上一次误差
    float integral;    // 积分累积
    float output;      // 输出值
    float out_max;     // 输出限幅
} PID_TypeDef;

// 增量式 PID 计算核心
float PID_Compute(PID_TypeDef *pid, float target, float measured) {
    pid->error = target - measured;
    pid->output += pid->Kp * (pid->error - pid->last_error)
                 + pid->Ki * pid->error
                 + pid->Kd * (pid->error - 2*pid->last_error + pid->prev_error);
    // 输出限幅
    if (pid->output >  pid->out_max) pid->output =  pid->out_max;
    if (pid->output < -pid->out_max) pid->output = -pid->out_max;
    pid->prev_error = pid->last_error;
    pid->last_error = pid->error;
    return pid->output;
}
```

## 六、总结与展望

### 6.1 工作总结

本项目完成了一款基于 STM32F407 + K230 + JY901S 的智能循迹小车系统，主要成果包括：

1. **双模切换策略**：在视觉循迹与 IMU 惯性导航间自动切换，解决了复杂路线下的连续控制问题
2. **三层 PID 闭环控制**：角度环 + 左右轮速度环构成完整的差速转向控制链
3. **4 套任务状态机**：覆盖直线、外圈、内切、多圈 4 类行驶任务
4. **完整的软硬件系统**：从 K230 端 Python 程序到 STM32 底层驱动，实现了端到端闭环

### 6.2 创新点

- **双模切换**中引入 `base_speed == 0` 作为强制盲开条件，将原地转向与视觉传感彻底解耦
- **原地转向**采用角度环 PD 控制器闭环，替代传统的开环延时 PWM，大幅提高转向精度
- **C 点精密对准**策略：角度误差 < 1° 方发车，有效抑制了盲开段的航向漂移
- **多圈展开状态机**：每圈独立参数，支持逐圈补偿轮胎磨损/打滑累积误差

### 6.3 有待改进的方向

| 方向 | 措施 |
|------|------|
| **加入前馈差速** | 圆弧段根据转弯半径预置左右轮速度差，减轻角度环 PID 负担 |
| **S 形速度曲线** | 在接近节点时平滑减速，提高停车精度并减少机械冲击 |
| **看门狗保护** | 启用 IWDG 硬件看门狗，防止程序异常时小车失控 |
| **编码器冗余校验** | 检测编码器计数突变，增加容错逻辑 |
| **自适应 PID** | 根据电池电压变化自动调整 PID 参数，补偿动力衰减 |
| **K230 通信 CRC 校验** | 增加帧完整性验证，避免传输干扰导致错误数据 |
